Mobile Application Permissions

Why the Before the Call mobile app requests each device permission, how each is used, and how users can manage them — least privilege, never for advertising.

01 Purpose

The Before the Call (“B4C”) mobile application may request access to certain device features in order to provide administrative functionality selected by the Customer.

This document explains why each permission may be requested, how it is used, and how users can manage these permissions.

Our goal is to request only the permissions necessary to provide the features chosen by the Customer while respecting user privacy and device security.

02 Our Permission Philosophy

Before the Call follows the principle of least privilege — we request only the permissions reasonably necessary to provide the features you enable.

Permissions are not requested for advertising, behavioral profiling, or unrelated data collection.

Many permissions are optional and are only requested when a user chooses to use a feature that requires them.

03 Camera Access

Why we request it

Camera access may be used to:

  • Scan training certificates
  • Capture department documents
  • Upload receipts
  • Add profile photos
  • Scan QR codes
  • Capture supporting documentation
  • Support future document scanning features

Required?

No. Camera access is optional unless a user chooses to use a feature that requires image capture.

If permission is denied

Users may still upload existing files or images where supported. Certain camera-based features will not function until permission is granted.

04 Photo Library Access

Why we request it

Photo library access may be used to:

  • Upload existing photos
  • Submit documentation
  • Add profile images
  • Attach supporting files
  • Upload department media

Required?

No.

If permission is denied

Users may be unable to upload existing images from their device.

05 File & Document Access

Why we request it

B4C may request access to files stored on the device in order to:

  • Upload SOPs
  • Upload training documents
  • Import administrative forms
  • Attach supporting documentation
  • Store exported reports where supported

Required?

Only when using features involving file uploads or downloads.

06 Notification Permission

Why we request it

Notifications help keep members informed of important administrative events, including:

  • Training reminders
  • Meeting reminders
  • Certification expiration notices
  • Department announcements
  • Assignment reminders
  • Task reminders
  • Fundraising events
  • Administrative deadlines

Marketing notifications are provided only where permitted by law and only if the user has opted in.

Required?

No. Disabling notifications will prevent reminder messages from being delivered to the device.

07 Location Services

Why we request it

Location services support optional administrative features such as:

  • Station Presence Verification
  • Automatic duty hour tracking
  • Attendance verification
  • Administrative reporting
  • Volunteer hour documentation
  • ISO support
  • Department-approved location events

Location information is used only for administrative purposes selected by the Customer.

Required?

No. Departments determine whether location-enabled administrative features are available. Users may control location permissions through their device settings.

Related documents

  • LOC-001 — Location Services Overview
  • LOC-002 — Station Presence Verification
  • LOC-003 — Location Privacy Policy

08 Background Location

Why we request it

Some optional administrative features require the application to recognize when a user enters or exits an approved department location even when the application is not actively open.

This allows Station Presence Verification to automatically document administrative events such as arrival and departure from approved department locations.

Background location is not used to continuously monitor users or build location histories.

Required?

Only for Departments using Station Presence Verification or other approved location-based administrative workflows.

User control

Users may disable background location through their device settings, although doing so may prevent certain automated administrative features from functioning.

09 Background App Refresh

Why we request it

Background App Refresh allows certain administrative tasks to continue updating efficiently when supported by the operating system. Examples include:

  • Synchronizing pending administrative records
  • Updating assigned tasks
  • Processing queued data
  • Improving notification reliability

The operating system ultimately determines when background refresh occurs.

Required?

No. Disabling this feature may delay synchronization until the application is reopened.

10 Biometric Authentication

Why we request it

Where supported, users may choose to unlock the application using:

  • Face ID
  • Touch ID
  • Fingerprint Authentication
  • Other supported biometric methods

Biometric information is processed by the device’s operating system. Big Bull Technologies does not receive, collect, or store biometric templates.

Required?

No. Users may continue using traditional authentication methods if available.

11 Future Permissions

As Before the Call evolves, additional permissions may become available to support new administrative features. Examples may include:

  • Microphone access for voice notes
  • Bluetooth for approved hardware integrations
  • Calendar integration
  • Contact sharing
  • Other device capabilities

Whenever practical, new permissions will be requested only when required for the selected feature. Material changes will be reflected in this document.

12 Managing Permissions

Users may review and modify application permissions through their device’s operating system settings.

Changing permissions may affect the availability or functionality of certain features.

Departments should communicate any organizational requirements regarding optional administrative workflows.

13 Privacy

Permissions granted to Before the Call are used solely to provide administrative functionality requested by the Customer.

Big Bull Technologies does not use application permissions to:

We do not

  • Deliver targeted advertising
  • Sell Customer information
  • Build behavioral profiles
  • Track users for marketing purposes
  • Collect information unrelated to platform functionality

Additional information is available in:

  • LEG-002 — Privacy Policy
  • LOC-003 — Location Privacy Policy
  • DAT-001 — Data Ownership Policy

14 Changes to This Document

Big Bull Technologies may update this Mobile Application Permissions document as new features become available or platform capabilities evolve.

Material changes will become effective on the published Effective Date after reasonable notice has been provided through the Services, our website, email, or another appropriate communication method.
